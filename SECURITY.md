# Security reporting

Please do not disclose exploitable vulnerabilities, credentials or private user
content in public issues or pull requests. If the GitHub repository offers private
vulnerability reporting, use its Security tab to submit a private report. If that
option is unavailable, ask a maintainer for a private reporting channel without
posting exploit details. No response-time guarantee is currently published.

Include the affected revision/version, prerequisites, impact, and minimal
reproduction steps using a disposable environment. Remove real credentials,
conversation contents and private certificates from attachments.

Security fixes and support claims must identify the exact affected component and
native version. The accepted local deployment does not establish general Internet
production readiness; consult the documented support matrix and deployment limits.

If a credential has been exposed, revoke or rotate it at its issuer. Removing it
from the latest file alone does not remove it from Git history or existing copies.
