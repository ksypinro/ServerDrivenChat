# Cline native controls (M20)

> **Current user instructions:** Start with the [M24/M25 beginner manual](guide/README.md). This document preserves its historical milestone/pin and implementation details; its old package names are not the current installation target.

## Scope and maintained boundary

The `sdc-m20.2` development build targets Cline 4.1.22 at commit `f58bc118bdeef1bd2813cd08e00d98bdcda96475`. It adds API 1.1 inside the application package. The companion consumes that app-owned public namespace; protocol, server and bridge modules remain vendor-neutral. [M19 evidence](../evidence/M19/live-vscode.json) remains historical evidence for its original build, not acceptance evidence for this expanded build. See the [M20 source patch](../extensions/vscode/patches/cline-v4.1.22-sdc-m20.2.patch) and [package fingerprints](../evidence/M20/artifact-manifest.json).

The native implementation captures Cline's actual interaction-coordinator promise resolver and tool-call/message identity. It publishes an opaque ask ID, immutable revision, task, native turn, full tool input and native preview, expiry and exact choices only after that resolver exists. A remote mutation checks the selected binding, captured task/session objects, native turn, request ID/revision, material, expiry, cancellation signal and authority. It checks all of them again after `assertAuthority()`, immediately before Cline's synchronous resolution method. Both native UI and addressed remote decisions consume the same captured native resolver. No generic Approve/Reject button command serves as the remote mutation interface.

The adapter derives the protocol action digest from the complete input and native preview with the protocol's canonical normalization. Its decision validator runs before native dispatch and checks the pending interaction again after asynchronous validation. App-layer rechecks additionally catch changes to the underlying tool input or preview. Duplicate decision IDs return recorded receipts without invoking a later ask; conflicting reuse fails. A local resolution is observable as `resolved_elsewhere`. A native question answer remains part of the current turn and does not trigger local takeover or a new remote turn.

## Permissions and cancellation

Only **Allow this whole action once** and **Deny this action** are exposed. Cline supplies no narrow-grant, turn/session grant, persistent-grant or revocation primitive for this route. Requests carry no fabricated permission grants. Nonempty grant lists and unoffered persistent choices are explicitly unsupported. Revocation is unsupported because no revocable grant was issued; it cannot undo an already executed action. Native auto-approval flags are observable through the allowlisted native snapshot and stay under Cline's settings. OS/login prompts still require local action. The pinned coordinator has one pending slot; concurrent manual interactions are rejected rather than replacing a pending resolver.

Cancellation targets the exact running native turn and captured SDK host/session. It raises Cline's native translator cancellation fence, settles pending native interactions, awaits that session's abort acknowledgement, then rechecks the binding/session before updating running state and recording the native resume ask. An abort failure or task switch after effects produces `unknown` and requires reconciliation without replay. It never updates a newly selected task after awaiting cancellation.

A question's `awaiting_followup` phase is not completion proof. API 1.1 also reports running state and the actual pending question. Completion requires native terminal phase and a stopped native session; cancellation requires an acknowledged abort and native resume ask. Unsupported or still-preparing control state returns unknown rather than an empty authoritative request list.

## Graphical controls and acceptance

Use **Cline Bridge: Select Existing Task**, **Review Pending Native Approval**, **Answer Pending Native Question**, and **Cancel Selected Native Turn** from VS Code's Command Palette. Review opens the complete native action in a JSON editor before offering the exact once/deny choices. A changed task/request fails at application dispatch. These controls are local graphical operations; authenticated server delivery remains the existing M11 runtime and M21 integration work.

The bounded **Run M20 Native Controls Probe (Disposable Task)** command is restricted to `/private/tmp/sdc-m19-vscode-probe`. It records addressed prompt/ask/decision IDs, full review material, native resolution events, observed file effects, native question output, abort/resume evidence and actual loaded bundle fingerprints. The probe pauses for a native local Reject click, then attempts an old remote allow while the next ask is pending. Both denied paths must stay absent. Persistent/narrowed grants and revocation must be rejected without consuming the pending ask. Approval settings must be identical before and after.

Run `npm run test:m20`, root build/lint/tests, and `python3 extensions/vscode/scripts/source-patch.py PATH_TO_PINNED_SOURCE` followed by a patch dry-run. Tests execute the exact pinned upstream interaction coordinator with message translator/UI dependencies stubbed. They establish concurrency behavior, not live application acceptance. No complete upstream source build, signing, distribution, Antigravity or remote-host compatibility is claimed. M20 is complete for the pinned local VS Code build: the [native acceptance trace](../evidence/M20/live-vscode.json) and [independent validation](../evidence/M20/live-verification.log) passed allow, deny, local-resolution/stale-decision race, question and acknowledged cancellation. The allowed file content and absence of both denied files were checked. Native Solar was restored and the bridge disconnected; see [verification and limitations](../evidence/M20/verification.json) and [native observations](../evidence/M20/native-observations.json). The loaded probe compared native auto-approval flags before/after and passed; the trace serializes only the initial flags. M21 remains separate.
