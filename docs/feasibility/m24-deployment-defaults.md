# M24 deployment choices — 2026-10-10

The user selected Docker deployment and MIT open-source licensing. ServerDrivenChat-owned code is covered by the root `LICENSE`; upstream Cline retains Apache-2.0 and dependencies retain their own notices. Native bundle hashes are unchanged by packaging the license.

## Recommended defaults

- **Target:** Docker Compose on the current development computer, reachable only from loopback. Keep PostgreSQL, server and gateway unpublished; expose Nginx on `https://localhost:15943`. A public domain or cloud account is unnecessary for this local deployment. Bind published ports explicitly to `127.0.0.1`, as described in [Docker port publishing](https://docs.docker.com/engine/network/port-publishing/).
- **Identity:** a genuine persistent Keycloak container, PostgreSQL-backed, with an `sdc` realm, a public `sdc-native` client, PKCE S256, the verified native callback and API audience `sdc-api`. Start Keycloak in its normal HTTPS mode rather than the disposable acceptance realm's development mode. The project provisions the realm/client and random administrator/database secrets; no external identity account is needed. See [Keycloak container deployment](https://www.keycloak.org/server/containers).
- **TLS:** a project-local certificate authority and localhost certificate. Trust only this CA on the test machine through the graphical OS certificate workflow. Persist its private key outside version control; never disable TLS verification. Route the identity realm through the same local HTTPS edge so the browser, native client and containers use one issuer URL.
- **Distribution:** versioned VSIX files and pinned container images for local installation. Generate a dedicated project-owned release-signing key, keep the private key outside the repository, and distribute a detached signature/public verification key with the integrity manifest. This proves project release integrity; it does not imply Microsoft Marketplace signing or approval. Public upload remains a separate instruction.
- **Native installation:** physically isolated VS Code user-data and extension directories, preserving the ordinary stock Cline installation. An operator-provisioned graphical launcher can avoid terminal product steps; [VS Code isolated instances](https://code.visualstudio.com/docs/configure/command-line) documents the isolation flags. Use the exact M30-accepted native code; install the MIT-notice-bearing M24 pair through the graphical Extensions interface.
- **Lifecycle:** persistent database/attachments; consistent stopped-writer backups; a clean-user native turn/control check; supported package upgrade, rollback and graphical uninstall/revocation/credential cleanup. Do not substitute container recreation for native package lifecycle.
