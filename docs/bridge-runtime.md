# Bridge runtime (M10)

`BridgeRuntime` in `bridge/src/runtime/` is the persistent non-LLM connection and scheduler layer. Construct it with one active session binding, its device credential, the M07 SQLite `BridgeStore`, and an `AppAdapter`. Multiple bindings run as separate runtime instances sharing one device-scoped `BridgeStore`. The store is the durable device router: intake accepts every authenticated device record, deduplicates repeated stream deliveries, and each scheduler dispatches only its session. Per-runtime connections use the same device-lane checkpoints; one binding cannot turn another binding’s legitimate record into a conflict. Call `start()` only after the graphical pairing/binding flow has selected the exact session. The runtime inspects native state and renews the lease before opening command or event streams.

The bridge opens separate authenticated fetch-based SSE streams for prompt and control lanes. It validates the command envelope and binding fence, stores each receipt durably, advances only contiguous lane cursors, and sends acknowledgements from a separate durable retry queue. This keeps a failed acknowledgement POST from losing the fact that a command was received. A separate control worker can cancel or answer an interaction while the prompt worker waits for a terminal app event. `approval.decide` is handed to an injected approval handler; without M11 that handler is not configured by the product shell. Steering is reported unsupported because the adapter contract does not yet expose a steering operation.

Before a native mutation, the runtime verifies the lease and reinspects the exact session/revision/generation, then rechecks cancellation and authority after inspection. It obtains a `POST /dispatch` admission channel holding the server’s binding/device/credential row locks, so a takeover cannot commit between admission and native mutation. It persists `applying` and the side-effect attempt atomically before invoking the adapter. App acceptance/application becomes a durable outcome. An unknown outcome or restart during `applying` becomes `reconciliation_required`; that command is never automatically resubmitted. Existing unresolved attempts pause normal prompt dispatch while independent control receipt and connection remain available.

Adapter output is persisted to the durable outbox before network transmission. A failed POST retries the same event ID and payload; the bridge clears it only after the server returns success. Outbox size and SSE frame size are bounded. Authentication failures stop and request credential repair. Binding/lease conflicts stop dispatch. Transient disconnections use jittered exponential backoff capped at 30 seconds. Lease renewal defaults to every 20 seconds against a 60-second server lease. The local deadline uses monotonic time at request start plus the server-derived remaining duration, deducting transit conservatively. A 1.5-second dispatch margin and independent watchdog stop dispatch even if renewal is hung; exhausted responses fail. Network requests have a 10-second timeout, and final jitter is capped at 30 seconds.

`disable()` immediately aborts local subscriptions, network tasks, and future app dispatch without contacting the server. A running app action is not claimed cancelled. The server stops command delivery when the lease expires; a later enable requires a current, unexpired binding and lease. `stop()` awaits runtime workers. The adapter subscription contract accepts an `AbortSignal` so shutdown does not depend on a model turn or an adapter event arriving.

Tests cover both a scripted loopback peer and the real HTTP API with PostgreSQL, including two simultaneous bindings, explicit obsolete-work skips, blocked cancellation/input/approval delivery, queued turns, takeover order, and retained output across a new producer epoch. All application execution uses the deterministic fake adapter. It is simulation evidence; no vendor application, production identity provider, or production deployment is established.

Startup establishes cancellation before its first await and rejects concurrent starts. Disable or stop during pending inspection cannot enable the bridge later. An `AdapterMutationContext` travels to every native mutation and the injected approval handler: adapters must invoke `assertAuthority()` at the actual effect boundary, honor the signal, and never defer a mutation beyond the permit deadline. The fake implementation checks this guard. The client monitors dispatch-channel closure and holds it only for admission/application acceptance, never for an entire model turn. Stop during an uncertain effect records reconciliation rather than replaying it. Real adapters must meet this contract in their own milestones; this implementation does not supply a vendor-native atomic approval resolver.

The `leaseExpiresAt` service getter is a local monotonic deadline in milliseconds, not an RFC 3339 wall-clock timestamp. Graphical shells should derive a remaining duration from their monotonic clock; the server response’s RFC 3339 expiry remains separate.
