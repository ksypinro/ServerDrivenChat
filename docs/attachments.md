# Attachments and artifact transfer (M13)

`AttachmentService` stores metadata/ownership in PostgreSQL and bytes under a private, opaque-ID filesystem root. Default limits are 20 MiB, seven days after commit, and one hour for incomplete uploads. The default MIME allowlist is PDF, JSON, UTF-8 plain/Markdown text, PNG, JPEG, and WebP; known types also receive signature/encoding checks. Configure a persistent private `rootDirectory`, limits, and allowlist for deployments. Keep that directory outside model-visible content and outside public web roots.

Create an upload with `POST /v2/attachments`, authenticated as a session operator/owner. Supply `X-Session-Id`, `X-File-Name`, `X-Content-SHA256`, `Content-Type`, and an exact `Content-Length`; the body is the raw binary content. The returned ID is pending. `POST /v2/attachments/{id}/commit` with `{ "sha256": "sha256:<64 lowercase hex>" }` verifies the staged size/hash, atomically renames the file, and then commits its metadata. A retry can finish metadata commit after interruption between those steps. Wrong owners, unsupported MIME types, size excess, incomplete content, or checksum mismatch fail explicitly. Incomplete uploads expire; committed content is automatically cleaned on the server's maintenance interval and may also be cleaned with `AttachmentService.cleanup()`.

Authorized session users can download committed content from `GET /v2/attachments/{id}`. The paired bridge can fetch only content belonging to its active session. Downloads are private/no-store, return the committed MIME, exact length, checksum and encoded filename, and are rehashed before serving. Ownership is checked independently of session visibility.

Before submitting a turn that references an image/file, `BridgeRuntime` fetches and rehashes every unique attachment, checks size/MIME/filename, probes the adapter's `stageAttachment` capability, and requires an exact applied receipt. It durably records each receipt before submitting the command. Unsupported or uncertain staging prevents the prompt from being sent; attachments are never silently omitted. The deterministic fake adapter retains the exact staged bytes and returns matching receipts. `artifact.available` references can be retrieved through the same authorized content route. App-specific native attachment confirmation remains M16/M19 work.
