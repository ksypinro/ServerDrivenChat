# Bridge storage

M07 adds `BridgeStore` in `bridge/src/storage/` using Node's built-in `node:sqlite` API and SQLite in WAL mode with `synchronous=FULL`. It has no server or network dependency. The local database stores received commands, per-device/per-lane contiguous receipt cursors, outgoing events, stable native-ID mappings, application attempts, and consumed decisions.

`acceptCommand()` commits the command and recomputes the cursor inside one `BEGIN IMMEDIATE` transaction. Out-of-order commands remain stored while the cursor stays at the last gap-free sequence; a later missing command advances only through already durable contiguous rows. Retries with the same identity and canonical JSON payload are duplicates; conflicting command IDs or sequence reuse raise `BridgeStorageConflict`.

Call `persistOutput()` before attempting transmission. The same event identity and content is idempotent, and `listUnackedOutput()` returns committed events until `acknowledgeOutput()` records a durable acknowledgement. Output IDs and `(sessionId,bridgeEpoch,eventSeq)` are unique. Producer replay checkpoints are contiguous within each session/epoch and include acknowledged history; a sequence gap cannot be hidden by taking the maximum. `persistOutput(input, maxUnacked)` applies a per-session pending-output limit after deduplication, so an identical replay remains valid at capacity.

Before an external application mutation, persist a pending attempt with `createAttempt()` and then call `markAttemptApplying()`. After a process restart, `recoverAfterRestart()` changes any still-applying attempt to `reconciliation_required`; it never automatically replays that action. Pending attempts that were never marked applying remain pending. The recovery result also includes cursors, inbox commands beyond each cursor, unacknowledged output, and recent consumed decisions so a later coordinator can inspect state before resuming.

`consumeDecision()` binds one local consumption to a session, request ID, revision, and action digest, and only permits an identical retry. Approval expiry enforcement and transmission remain outside this storage-only milestone; expired approvals must not be replayed by a later coordinator.

The schema is created idempotently. Version 2 transactionally migrates existing output into epoch-aware uniqueness while preserving payloads, timestamps and acknowledgements. The epoch is recovered from each old protocol envelope; rows without one use a distinct `legacy` epoch. Node 24.21.0 now passes fresh setup and the SQLite acceptance suites. This module keeps M07's TypeScript bridge boundary; the companion's future platform integration must continue to use the same SQLite durability and recovery semantics.

`acceptSkip()` persists a server-authenticated `command.skipped` tombstone atomically with contiguous receipt advancement. Unknown holes still block dispatch. A tombstone names only its device, lane, sequence, command ID and obsolete-binding reason; it cannot inject an app command or silently skip unrelated work. Repeated conflicting tombstones fail. Each binding's scheduler and acknowledgement/output readers are scoped to its session, while device-lane receipts share one durable inbox. Recovery can be scoped to a session to avoid marking another binding's live attempt uncertain.
