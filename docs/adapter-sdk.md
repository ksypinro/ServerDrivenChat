# Adapter SDK and fake implementation

`@server-driven-chat/adapter-core` exposes the `AppAdapter` operation interface and common protocol types. Implementations preserve the user-selected native conversation and opaque native identifiers. Each non-streaming operation returns `accepted`, `applied`, `rejected`, `unsupported`, or `unknown`; uncertainty must remain `unknown` rather than being reported as success. Stream setup failures use `AdapterStreamError` with the same explicit outcome distinction.

Capabilities report supported, unsupported, or unverified operations with a reason and optional evidence reference. An adapter is responsible for exact binding identity, request ID/revision checks, and honest native evidence. A successful local result must not be described as proof of a remote application effect.

`@server-driven-chat/adapter-fake` is a deterministic in-memory test double. Inject `now`, a scripted turn, unsupported operations, and per-operation fault queues through `FakeAppAdapterOptions`. Its events, operation evidence, app version, and IDs are visibly simulated; it does not launch or connect to an application. Scripts can emit partial/replaced output, suspend at an input or approval request, then resume; queued prompts remain behind the suspended turn. Local control methods accept only the exact pending request identity and revision. Cancellation can stop a suspended fake turn. These behaviors support contract tests only.

Reusable fixtures live under [`tests/fixtures/adapter/`](../tests/fixtures/adapter/): streaming partial/replacement/completion and a suspended input with a queued prompt. `tests/adapter.test.mjs` exercises deterministic replay, selected identity, queue ordering, input and approval controls, cancellation, unsupported operations, and injected unknown outcomes. This is not a real-app conformance result. Future adapters must use their own app-owned evidence and pass equivalent contract tests.

Producer replay checkpoints use `ProducerCursor {bridgeEpoch,producerSeq}`, separately from command-lane cursors; sequence numbers are scoped to the session/epoch, not a session-wide maximum. The fake can inject `sessionId` and `bridgeEpoch` for multi-binding/restart fixtures. Scripted approval requests must belong to the exact fake binding and turn; foreign identities are rejected before starting the turn. Its native approval resolver compares complete review content with the stored pending native request before deriving choices or grants.

Bridge mutation calls supply an `AdapterMutationContext` with a signal and synchronous `assertAuthority()` guard. An adapter must call the guard immediately at every external effect boundary, including after its own asynchronous preparation, and must never queue that effect beyond the permit. The fake rejects deferred queue delivery when operating under a guarded bridge call. Legacy direct simulator calls without context remain available for isolated SDK fixtures; they are not production bridge permission evidence.

`stageAttachment` is an optional adapter method backed by the `stageAttachment` capability. A bridge only calls it after authorized retrieval, local size/MIME/checksum/filename verification, and a supported capability result; it requires an `applied` receipt matching the committed attachment exactly before submitting the prompt. The fake retains exact staged bytes and returns simulation-only receipts. A native adapter must identify where those bytes will be consumed and must not treat staging as proof of app-level attachment confirmation.
