# Cline task bridge development packages

The maintained Cline 4.1.22 development route includes M19 task binding and M20 native request controls. M19 is accepted on its recorded build; the expanded M20 build passed its own [native controls acceptance](../../evidence/M20/verification.json). See [the bridge contract and acceptance procedure](../../docs/cline-bridge.md) and [DECISION-004](../../docs/decisions/004-cline-extension.md).

Build from the repository root with `npm run build`. The historical M21 generator is `package-development.mjs`; it now refuses the current companion version before overwriting historical artifacts. For the current M22 companion use `node extensions/vscode/scripts/package-m22.mjs` with the preserved M21 native directory. The script verifies the exact vendor bundle fingerprint, copies it into `dist/`, inserts the app-owned API at its public export boundary, and produces two unsigned development VSIX files. It never edits the source installation. An unrecognized version or fingerprint is rejected.

For development, launch VS Code's Extension Development Host with both generated extension directories and a disposable workspace. Select **Cline bridge** in the status bar, confirm the exact existing sidebar task, and inspect readiness. A native live session must already exist; opening a historical task alone does not authorize the bridge to create another session. The graphical **Cline Bridge: Run M19 Two-Message Probe (Disposable Task)** command sends two bounded harmless turns, checks exact native input echoes, observes native output and terminal events, and saves `m19-live-evidence.json` in that workspace. Its **Text and PNG** mode includes a valid 64×64 PNG and requires an image-capable native model. **Text only** explicitly records image acceptance as untested. Use it only in a disposable task. The second prompt asks for the marker from the first without repeating it.

Every task/workspace change, local prompt takeover, or extension-host reload requires explicit selection again. **Disconnect** detaches the bridge and preserves the native task. Only local VS Code is supported by this package; Antigravity 3.83.0, remote extension hosts, stock Cline, and other Cline versions are rejected. API 1.1 provides graphical **Review Pending Native Approval**, **Answer Pending Native Question**, and **Cancel Selected Native Turn** commands. Whole-action once/deny choices are supported; narrowing, persistent grants and revocation are explicitly unsupported. Read the [M20 controls contract](../../docs/cline-controls.md). The new packages are `dist/cline-4.1.22-sdc-m20.2` and `dist/sdc-cline-bridge-m20`; the original M19 artifacts are preserved separately. The companion directory name includes M20, but its stable extension identity is `server-driven-chat.sdc-cline-bridge` so public API lookup resolves the loaded companion. The M20 native probe is restricted to `/private/tmp/sdc-m19-vscode-probe` and pauses for a native local Reject click. It verifies actual action outcomes and cancellation evidence, not just method returns. Connect/pairing is M21, and signing/publication is M24.
